## The problem

Given a bacterial protein sequence, predict which class of antibiotic it confers resistance to. 6,088 sequences from the CARD database (v3.2.4), sorted into 11 resistance categories.

The dataset had a property that determined the entire project: **one class held roughly 80% of it.** Several of the remaining classes had fewer than 200 sequences each — and those rare classes included carbapenem resistance, which is clinically among the most consequential things on the list.

So the naive success metric is actively misleading. A model that ignores the input and always predicts the majority class scores 80% accuracy while being medically useless, because it never once flags the resistance you most need to catch.

**Result:** XGBoost at 94.2% accuracy (±0.2%) under stratified 5-fold cross-validation — but the number that matters is a macro-F1 of 0.71 against Random Forest's 0.56, driven by recall on the minority classes: carbapenem 0.17 → 1.00, aminoglycoside 0.42 → 0.89.

## How it works

**Parse.** Biopython reads the CARD FASTA files; regex extraction pulls ARO ontology terms; keyword classification maps them into the 11 resistance categories.

**Featurize.** Protein sequences get treated as text — 6-mer extraction (169K unique k-mers across the corpus) followed by TF-IDF vectorization.

**Train and evaluate.** Random Forest and XGBoost compared under stratified 5-fold cross-validation, scored on macro-F1 rather than accuracy.

## Decisions worth explaining

### Macro-F1 as the primary metric

This is the decision the whole project rests on. Accuracy on an 80/20-skewed dataset measures almost nothing — a majority-class predictor achieves 80% without learning anything. Macro-F1 averages F1 across classes without weighting by class size, so a class holding 3% of the data contributes exactly as much to the score as the class holding 80%.

That reframes what a "good" model is. The 15-point macro-F1 gap between XGBoost and Random Forest is a much more meaningful result than either model's accuracy figure, and if I'd optimized for accuracy I would likely have shipped the worse model.

### K-mers instead of alignment-based features

Treating a protein sequence as a document of overlapping 6-character substrings makes standard text-classification machinery apply directly. It also throws away long-range structure — a k-mer representation has no idea two motifs 300 residues apart are related.

k=6 is the conventional choice in protein k-mer work and I took it as a default rather than deriving it. I never swept k, so I don't actually know whether 5 or 7 would have performed better — which is a cheap experiment I should have run.

### Conservative augmentation instead of SMOTE

To address the imbalance, I generated 1,348 synthetic sequences by applying 5%-rate amino-acid mutations to minority classes with fewer than 200 examples, expanding the training set from 4,692 to 6,040.

SMOTE is the reflexive choice here and it's the wrong one for this data. SMOTE interpolates between points in feature space — and the feature space here is 169K-dimensional TF-IDF over k-mers. A point halfway between two sequences in that space doesn't correspond to any actual protein; it's a k-mer histogram that no sequence could produce. Mutating at the sequence level and re-extracting features keeps every synthetic example a real, biologically plausible sequence. The 5% rate is deliberately low for the same reason: enough variation to be useful, not enough to mutate a sequence out of its own resistance class.

## The result I don't fully trust

Carbapenem recall went from 0.17 to 1.00. Perfect recall on the rarest and most clinically important class is the best-looking number in the project, and it's the one I'd interrogate hardest.

**The specific concern is fold contamination.** If augmentation happened before the cross-validation split, then mutated copies of a sequence can land in the training fold while the original sits in the test fold. At a 5% mutation rate those are near-identical, so the model is effectively being tested on data it trained on — and minority classes, which received the most augmentation, are exactly where that inflation would concentrate.

**Augmentation ran before the split.** Synthetic variants were generated from the full filtered dataset, concatenated with the originals, and only then divided into train and test. So a sequence and its three mutated copies were shuffled across both sides — and at a 5% substitution rate restricted to same-chemistry residues, those copies are nearly identical in k-mer space. The model was partly evaluated on data it had trained on, and because only classes under 200 examples were augmented, the inflation lands precisely on the minority classes this project is about.

The reported minority-class recall should therefore be read as an upper bound, not a measurement.

With a class of that size, a single test-fold example flipping also moves recall by a large fraction, so the confidence interval around 1.00 is wide regardless.

## What I'd do differently

**Restructure the pipeline so nothing leaks.** Split first, then fit the vectorizer and generate augmented examples inside the training fold only, and hold out a separate validation split for early stopping — right now the test set selects the stopping iteration.

**Validate the label mapping.** The 11 resistance categories come from keyword-matching ARO ontology terms. That step is rule-based and I never checked it against ground truth, so an unknown fraction of my labels may be wrong, which would cap achievable accuracy regardless of the model.

**Try a protein language model.** ESM-2 embeddings as a baseline against k-mers would answer whether sequence structure carries signal a bag-of-k-mers discards. That's the obvious next experiment and I haven't run it.
